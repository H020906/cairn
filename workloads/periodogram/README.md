# Lomb–Scargle periodogram

**The first workload in this repository that is science rather than a fixture.**

Given observations `(t, y)` taken at uneven intervals — which is what a telescope produces, because
of daylight, weather and scheduling — this finds how much periodic power the series contains at
each of a set of frequencies. A peak is a candidate period: a variable star, a binary, a transiting
planet, a pulsar.

A **work unit is one frequency band**. Split the search across bands and you have exactly the shape
of work Cairn exists for: independent, no shared state, no ordering.

## Run it

```bash
cargo build --release --manifest-path workloads/periodogram/Cargo.toml

cargo run -p cairn-worker -- run \
  workloads/periodogram/target/wasm32-unknown-unknown/release/cairn_periodogram.wasm \
  workloads/periodogram/band-with-the-signal.bin
```

The two committed inputs are the same 120 observations scanned over two different bands — which is
how a real search is divided among volunteers. The signal is at **0.137 cycles/day**, so
`band-with-the-signal.bin` covers it and `band-without-it.bin` does not:

| unit | peak | power |
|---|---:|---:|
| `band-with-the-signal.bin` | **0.1370 c/d** | **58.1** |
| `band-without-it.bin` | 0.5331 c/d | 1.8 |

**Run both.** The second one is not padding — it is the calibration. Its "peak" is the largest
fluctuation in noise, and a power of 1.8 is what noise is supposed to give: this workload
normalises by the variance, which makes the power at each independent frequency exponentially
distributed with mean 1 under the null hypothesis. Without that number, 58.1 is just a number.

Both are regenerated by the test that checks them, so they cannot drift from the thing that
asserts they are right:

```bash
CAIRN_REGENERATE_INPUTS=1 cargo test -p cairn-runtime --release --test differential a_periodogram
```

## Input and output

Little-endian throughout.

```text
input   f64  lowest frequency in the band
        f64  highest frequency in the band
        u32  how many frequencies to sample across it
        u32  how many observations follow
        (f64 time, f64 value) × that many

output  f64  the frequency with the most power
        f64  that power
        f64  the sum of the power at every frequency scanned
```

The third output field is for **verification rather than science**. The peak alone would hide a
disagreement anywhere else in the band — two volunteers could differ at nine hundred frequencies,
agree on the peak, and the grid would accept it. The sum is affected by every frequency scanned.

## Why this kernel, and why it could not have been written earlier

A periodogram is `sin` and `cos` and almost nothing else. **WebAssembly has neither.** Before
[ADR-0016](../../docs/adr/0016-math-belongs-in-the-module-not-the-host.md) the only way to get them
was to import them from the host — and the measurement there is that V8 and the platform libm
return different bits on *every one* of twelve functions tried, and that the platform's `sin` is
outright wrong for the worst case in the format.

A kernel calling `sin` a million times per unit would have manufactured disputes at roughly that
rate, and arbitration would have convicted whichever honest volunteer happened to be on the losing
engine. That is why the roadmap put the math library before the science, and it is the ordering
argument to defend if anyone proposes doing a real workload first: **a genuine numerical kernel is
exactly where a float divergence hides**, so it would have produced a dispute rate nobody could
explain on a computation nobody could check.

## What Cairn does and does not promise about the answer

**The result is not the mathematically exact periodogram.** It is a specific, reproducible sequence
of `f64` operations that approximates it. Floating-point addition is not associative, so the order
of every sum is part of the answer — the loops run sequentially over the input in the order it
arrived, with no parallel reduction and no compensated summation.

Cairn verifies that two volunteers computed **the same thing**. Whether that thing is the right
science remains the workload author's problem. A more accurate summation here would be a *different*
answer rather than a better one, and would be perfectly fine — but only if every volunteer changed
at the same instant, which is what the unit id being a hash of the module bytes enforces.
